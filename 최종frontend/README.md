# 캡스톤 새 프론트엔드

Figma Make에서 2026-10-31 내보낸 최신 디자인 코드입니다.

현재 작업 위치: `캡스톤디자인_dev/최종frontend`
기존 기능 참고용 프론트는 `../frontend`, 공용 백엔드는 `../backend`입니다.

원본: https://www.figma.com/make/2wyZZiUuBa6yBzYiTxDSNy

## 현재 상태

- React 19 + TypeScript + Vite + Tailwind CSS 4
- 홈, 시작 전 안내, 면접, 분석 대기, 결과 화면을 포함한 디자인 프로토타입
- 질문 목록은 제출 완료된 질문만 내용 공개
- 전체 종합·항목별·질문별 평가는 모델의 `percentile`을 ‘백분위’ 숫자로 표시. 100점 만점 변환은 하지 않음
- `band`는 사용자 결과 화면에서 숨기고 API 원본에는 보존. LLM 호출은 아직 미연결
- 질문별 답변 텍스트(`transcript`) 표시. 백분위가 없으면 ‘정보 없음’ 표시
- 결과 화면의 다시 연습하기 버튼 제거
- 질문 패널 높이 고정, 긴 질문 글자 크기 자동 맞춤
- 안내 화면에서 면접 시작 시 `POST /api/interviews`로 기존 백엔드의 실제 질문 5개와 세션 ID를 받음
- 로딩 중 중복 요청 방지, 오류·재시도, 15초 응답 제한, 화면 이탈 시 요청 취소 지원
- 안내 화면에서 실제 카메라·마이크 권한 요청, 실시간 영상, 마이크 입력 음량 표시 제공
- 장치 두 개 연결과 동의 후 면접 시작 가능. 면접 화면에서도 같은 스트림을 재사용
- 처음으로/면접 나가기/페이지 종료 시 장치 해제. 권한 거부·장치 없음·분리 시 오류 및 재연결 안내
- MediaRecorder로 실제 영상·음성 녹화, 최대 60초 자동 종료, 질문별 녹화 2회
- 녹화 종료 후 재생·소리 확인 가능한 영상 미리보기
- 질문 문장 바로 옆 스피커 버튼으로 브라우저 영어 음성 읽기 → 녹화 화면 중앙에 5초 카운트다운 → 자동 녹화. 준비 시간은 녹화 시간에 포함하지 않음. 면접 시작 전 안내에도 이 흐름 표시
- 읽기 중지·카운트다운 취소 가능. 직접 녹화 시작 시 읽기와 카운트다운 중단. 녹화/미리보기 중 질문 읽기 비활성화
- 질문 전환·장치 연결 해제·화면 이탈·탭 숨김 시 음성과 대기 중 자동 녹화 취소. 음성 미지원/실패 시 직접 녹화 가능
- ‘이 답변 제출하기’ 한 번으로 질문별 영상 저장 API 호출, 저장 성공 후 다음 질문 이동
- 저장 중 중복 제출·다시 녹화 방지, 실패 시 영상 유지 및 재제출 지원
- 마지막 답변까지 저장되면 Figma Make에서 가져온 답변 확인 화면 표시: 왼쪽 질문·영상, 오른쪽 제출한 질문 5개 목록
- 실제 세션·질문 ID의 영상 조회 API로 서버 저장 파일 재생. 질문 전환 시 기존 재생 정지·위치 초기화, 재생/음소거 아이콘 및 오류 재시도 지원
- 답변 확인의 ‘분석 시작하기’로 분석 API 호출 → 대기 화면 → 결과 화면 이동. 실패 시 오류와 분석 재요청·답변 확인으로 돌아가기 제공
- 분석 대기는 STT 텍스트 변환 → 텍스트를 확인하며 평가 대기 → 최종 결과 순서. `/transcripts` 응답을 받은 뒤 `/analyze` 호출
- 대기 화면은 질문별 텍스트 선택·읽기 제공. 평가 실패 시 준비된 텍스트 유지. 재요청 시 서버에 저장된 STT 재사용
- 전체 평가는 `session.scores`, 질문별 평가는 `videos[].scores`, 답변 텍스트는 `videos[].transcript` 사용. 세션·질문 ID와 순서 검증 후 표시
- 평가가 없으면 ‘평가 정보 없음’, 빈 STT는 ‘인식된 답변 텍스트가 없어요’ 표시. 예시 점수·LLM 피드백으로 대체하지 않음
- `is_dummy=true`일 때 테스트 결과 안내를 표시. 실제 결과에는 테스트 안내를 표시하지 않음

## 로컬 사용 준비

Node.js 20.19 이상 또는 22.12 이상이 필요합니다. 현재 PC의 기본 Node 20.10은 이 프로젝트의 Vite 버전과 맞지 않습니다. 이번 검증에는 Codex 번들 Node 24.22.1을 사용했습니다.

프로젝트의 pnpm-lock.yaml을 함께 가져왔습니다. 지원되는 Node에서 의존성을 설치한 후 아래 명령을 사용할 수 있습니다.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

빌드는 `pnpm build`, 타입 검사는 `pnpm exec tsc --noEmit`입니다.
API 응답·오류 처리 테스트: `node --test tests/interview-api.test.mjs`
분석 결과 검증 테스트: `node --test tests/analysis-api.test.mjs`
질문 읽기·카운트다운 테스트: `node --test tests/question-narration.test.mjs`
`/tests/question-narration-browser.html`은 가상 음성 종료 이벤트와 테스트 스트림으로 자동 녹화·취소를 검증합니다. 실제 음성 출력이나 서버 저장은 하지 않습니다.

장치 연결·해제 테스트 포함: `node --test tests/*.test.mjs`

개발 서버에서 `/tests/recording-browser.html`은 테스트 그림·음성으로 실제 녹화 및 저장 API를 검증합니다. `/tests/interview-flow.html`은 같은 테스트 스트림으로 실제 면접 컴포넌트의 녹화·재녹화·제출·다음 질문 흐름을 검증합니다. 두 화면 모두 실제 카메라·마이크 권한을 사용하지 않으며 제품 화면에는 연결되지 않습니다. 테스트 시에도 백엔드 uploads에 테스트 영상이 저장됩니다.

## 기존 백엔드 연결

Vite 개발 서버가 `/api` 요청을 `http://127.0.0.1:8000`으로 전달합니다. 기존 `../backend`에서 아래 명령으로 백엔드를 실행합니다.

```powershell
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

질문·영상 저장에는 Colab이나 Gradio 주소가 필요하지 않습니다. 실패 시 고정 예시 질문으로 대체하지 않고 안내 화면에서 재시도합니다. 질문 목록에는 현재·미래 질문의 내용을 표시하지 않습니다. 영상은 `POST /api/interviews/{session_id}/answers/{question_id}`로 저장되며 공용 백엔드의 `uploads/{session_id}` 폴더에 질문별 WebM과 manifest가 남습니다. 제출 응답 제한은 120초이며, 실패 시 영상은 현재 화면 메모리에 유지됩니다. 새로고침/나가기를 하면 미제출 영상은 사라집니다.

## 카메라·마이크 확인

로컬 화면 → 면접 시작하기 → 카메라 확인 또는 마이크 확인 → 브라우저에서 두 장치 허용. 두 버튼은 하나의 연결 요청을 공유합니다. 실시간 미리보기가 나오고 말할 때 음량 막대가 반응하는지 확인한 뒤 동의하고 면접을 시작합니다. 미리보기는 좌우 반전하고 소리는 스피커로 재생하지 않습니다.

장치 점검 중에는 미리보기만 합니다. 면접에서 ‘녹화 시작’을 눌러 녹화하고 ‘녹화 마치기’ 또는 60초 자동 종료 후 영상의 재생 버튼으로 영상·소리를 확인합니다. ‘이 답변 제출하기’를 눌러야 서버에 전송됩니다. WebM 녹화를 지원하는 Chrome/Edge를 사용합니다. 외부 도메인의 Figma Make 화면에는 로컬 변경이 자동 동기화되지 않으므로 `http://127.0.0.1:5174/` 등 실행 중인 로컬 주소에서 확인합니다.

## 원본 보관과 로컬 설정

- 디자인 원본은 `디자인자료/references`에 보관하며, 현재 `src`에는 실제 질문 API 연결 변경이 포함돼 있습니다.
- Figma 내부 실행용 Vite 플러그인을 일반 로컬 개발 설정으로 교체했습니다.
- HTML의 Figma 전용 제목·언어 자리표시자를 실제 값으로 바꿨습니다.
- 원본 전체 ZIP과 Make 파일은 `디자인자료/references` 폴더에 보관합니다.
- 기존 `frontend`와 `backend` 코드는 그대로 보관합니다.

결과 UI만 확인하려면 개발 서버의 `/tests/results-preview.html`을 엽니다.
이 페이지는 별도의 테스트 데이터로 화면만 표시하며 모델을 호출하거나 영상을 저장하지 않습니다.

실제 분석에는 백엔드의 `GRADIO_API_URL` 설정과 실행 중인 Colab 모델 서버가 필요합니다.
STT와 평가 응답 제한은 각각 6분입니다. 모델 서버 미설정/호출 실패 시 오류를 표시하고 자동으로 더미 결과를 만들지 않습니다.
`/tests/analysis-preview.html`에서 텍스트 변환 중·준비 완료·평가 실패 상태를 테스트 데이터로 확인할 수 있습니다. 모델을 호출하지 않습니다.
점수 변환과 LLM 평가 방식은 결정 후 연결합니다.
