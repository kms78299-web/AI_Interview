# LLM 프롬프트 비교 실험 (모델 정보 A/B/C)

## 1. 왜 하는가

점수 모델(MiniCRMF)은 **사람 단위로만** 평가자 판단과 맞는다(Spearman 약 0.73).
같은 사람의 답변끼리는 거의 구분하지 못하고(0.15~0.18, 길이 영향을 빼면 약 0.07), 내용을 보지 못하며, 짧게 말하는 사람을 높게 보는 경향이 있다(`model/API.md` 2장).
그래서 서비스에서는 숫자 점수를 보여주지 않고, 모델 결과를 Gemini 프롬프트에 **참고 정보 한 줄**로만 넣는다.

남은 질문은 이것이다.

> 모델 결과를 프롬프트에 넣는 것이 피드백을 좋게 만드는가, 아니면 오히려 근거 없는 말을 만들게 하는가?

이 실험으로 정하려는 것:
- 모델 정보를 프롬프트에 **넣을지 뺄지**
- 넣는다면 **성능·편향 설명까지 같이 넣어야 하는지**

## 2. 세 가지 조건

대본, 측정값, 구간 마커, 작성 규칙, 출력 형식은 셋 다 같고 **모델 정보의 양만** 다르다.

| 조건 | `/analyze` 응답 필드 | 들어가는 모델 정보 | 확인하려는 것 |
|---|---|---|---|
| A. 모델 없음 | `session.llm_prompt_compare.no_model` | 없음. "모델"이라는 말도 나오지 않는다. | 측정값과 대본만으로 피드백이 얼마나 정확한가 (기준선) |
| B. 모델 출력만 | `session.llm_prompt_compare.model_output` | 사람 단위 전반적 인상(상/중/하) + "RecruitView 평가자 판단을 학습한 모델" 한 줄 | 설명 없이 결과만 주면 LLM이 그걸 근거로 지어내는가 |
| C. 모델 + 성능·편향 (서비스 기본) | `session.llm_prompt` | B + 성능(Spearman 약 0.73), 한계(답변 비교 불가, 내용 못 봄, 간결한 사람을 높게 봄), "모델 인상을 등급으로 옮기지 않는다" 규칙 | 한계를 알려주면 B의 문제가 줄어드는가 |

- C는 B를 그대로 포함한다. 그래서 B와 C의 차이는 "성능·편향 설명을 더한 효과"만 남는다.
- A의 짧은 답변 표시는 "모델 점수에서 제외됨" 대신 "답변이 매우 짧음"이다.
- 코드: `model/code/session_prompt.py`의 `build_session_prompt(..., model_info="none" | "output_only" | "full")`

**서비스에서는 `session.llm_prompt`(C)만 쓴다.** A와 B는 실험용이며, 백엔드는 이 두 필드를 무시하면 된다.

## 3. 예상과 판단 기준

| 결과 | 해석 | 결정 |
|---|---|---|
| A ≈ C, B에서 모델을 근거로 든 문장이 나옴 | 모델 정보가 도움은 안 되고, 설명 없이 주면 해롭다 | 모델 정보를 빼거나(A), 넣더라도 C 형태로만 |
| C가 A보다 사람 단위 판단(전반적 인상)에서 더 사람 평가와 맞음 | 모델이 참고 신호로 기여한다 | C 유지 |
| A, B, C 모두 비슷함 | 모델 정보가 출력에 거의 영향을 주지 않는다 | 단순한 A도 가능. 모델은 별도 표시용으로만 |

비교 결과 숫자는 조정하지 않고 그대로 기록한다.

## 4. 미리 찍은 영상으로 돌리는 법

팀 UI는 WebM 녹화만 받고 Gemini를 아직 부르지 않으므로, **Colab Gradio 서버에 직접** 영상을 보낸다.
Drive의 `model` 폴더가 최신 코드인지 확인하고 Colab을 다시 켠다.

**웹 페이지로:** `gradio.live` 주소를 열고 영상을 질문 순서대로 올린다.
`transcripts_json`은 **비우고**(그래야 STT가 문장 구간과 마커까지 만든다), `questions_json`에 질문 리스트를 넣고 "점수 분석"을 누른다.
결과 JSON의 세 필드를 각각 Gemini에 보낸다.

**스크립트로:** `model/compare_prompts.py`가 같은 호출을 하고 프롬프트 세 개를 파일로 저장한다.

```bash
pip install gradio_client
python model/compare_prompts.py --url https://xxxx.gradio.live \
    --videos q1.mp4 q2.mp4 q3.mp4 q4.mp4 q5.mp4 \
    --questions questions.json --out runs/session01
# -> runs/session01/result.json, prompt_A_no_model.txt, prompt_B_model_output.txt, prompt_C_full.txt
```

- mp4, mov, webm 모두 된다. 13단어 미만이거나 7초 미만인 답변은 짧은 답변으로 처리된다.
- 얼굴이 잘 보이게 찍어야 시선·얼굴 마커가 의미 있다.

## 5. 비교 방법

1. 같은 세션의 프롬프트 세 개를 **같은 Gemini 모델, 같은 설정**으로 보낸다. 조건마다 3번 이상 반복한다.
2. 세션마다 아래를 기록한다.

| 항목 | 보는 것 |
|---|---|
| `overall_band`, 질문별 `content_band` | 조건에 따라 바뀌는가, 사람이 본 판단과 맞는가 |
| 대표 장면(`evidence`) | 조건에 따라 같은 구간을 고르는가 |
| 근거 없는 문장 | 측정값·대본에 없는 내용, "모델 점수가 높아서" 같은 설명이 있는가 (개수) |
| 반복 일관성 | 같은 조건을 여러 번 돌렸을 때 등급과 장면이 같은가 |

3. 가능하면 세션을 여러 사람·여러 수준(잘한 답변, 일부러 못한 답변)으로 준비한다. 한 세션만으로는 결론을 내지 않는다.
